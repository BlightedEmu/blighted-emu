# M3 exit test

Date: 2026-09-02. Commit: `c642d7a` (plus the test client and gateway built from it).

This note records the M3 exit test of spec `2026-09-02-m3-rep-gateway-design.md` section 1.2. The game was not run. The test client (`nw-testclient`) did the steps that the game does. The game cannot finish DTLS with this gateway, because it trusts only its built-in certificate (spec section 1.3).

## Set-up

- One PC. Docker PostgreSQL and Valkey (`just infra-up`).
- `edge-http serve` on port 443 with the operator's own domain and certificate. `rep_address` is `127.0.0.1:33435`.
- `rep-gateway serve` on UDP port 33435, with a certificate from `rep-gateway generate-certificate`.
- Both servers use the same `NW_SECRET_SIGNING_KEY`. The secrets are in a git-ignored local file.
- `nw-testclient` with the committed example config, the login and game URLs set to the domain, and `hold_seconds = 60`.

## Result

| Criterion | Result |
|---|---|
| 1. `cargo test --workspace` passes | Pass. 0 failed. |
| 2. `content-tool capture-check` reads every local ledger with 0 decode errors | Pass. 285 files, 7,211,869 datagrams, 7,223,978 messages, 0 decode failures. 43 registration responses, all status 0. Exit code 0. |
| 3. Live test | Pass. See below. |

**Observed.** The test client printed these lines (exit code 0):

```text
account testclient ready
character Testclient in world 8d0f4c2e-0000-4000-8000-000000000001
queue admitted; gateway 127.0.0.1:33435
registration status 0, server version [BLIGHTED].Javelin.1.365.6031.6004151
held 60.0 s: 59 pings echoed, closed by server: false
second registration with the same ticket: status 1
```

**Observed.** The gateway logged `registration accepted` for the first registration. It logged `registration refused` with reason `unknown_ticket` for the second registration, 60 s later. The log masks the ticket.

**Observed.** Two runs were done, about one minute apart. Both runs gave the same result.

## What this proves

- The login flow of M2 gives a ticket that the gateway accepts.
- DTLS 1.2 with the client's cipher, the carrier connect, the V3 registration, and the registration response work between two programs that this project wrote.
- The connection stays up for 60 s. The server sends a ping about every 1 s, and the client echoes each ping.
- A ticket works one time only.

## What this does not prove

- The game itself connecting to the gateway. That is blocked by the game's built-in certificate trust, and this project does not change it (spec section 1.3).
- Any message after the registration response, except the ping (M4).
