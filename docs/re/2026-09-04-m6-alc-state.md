## Round 4

The child table in the movement message note is unchanged. This round checks the three checks the capture tool rejects: a blob count, a bounds flag, and a prefix cut short.

**Observed.** `FUN_142a43140` reads a short prefix count and accepts it only when the count is below `0x21` (33). It then reads that many bytes. `FUN_142a43230` is the same with the limit `0xb1` (177). `FUN_142a43020` reads one flag byte. A value of 2 or more fails. A value of 0 stops. A value of 1 reads 16 bytes (`FUN_1417b11d0`), one byte, and one more flag byte. That second flag also fails when it is 2 or more, and it does not open another 16-byte block. The `quat` extra-byte count in `FUN_14087a8d0` matches the movement message note.

**Inferred.** `crates/nw-messages/src/alc.rs` uses those limits and that flag rule. It does not miss a form that these functions read.

**Observed.** Of the 176 capture-check failures, 9 fail inside a class 11 member that follows a vitals member: 6 counts at or above 33, 2 counts at or above 177, and 1 flag byte other than 0 or 1. One of the counts is the same integer as class 3139. The client functions above reject those values. A higher limit would not be the client's read.

**Observed.** 57 further failures are a class 15 body that ends early after a class 11 member the type 11 reader accepted. 1 is a class 13 child-bit failure after a class 11 member. Those 58 are not a type 11 size: the type 11 member is already in the accepted prefix. The vitals note covers the 57.

**Observed.** 49 of the 176 fail before a member reader returns, on a prefix that is cut short or a group header. 2 are a payload whose members match and whose whole encoding does not. This round does not assign those 51 to a type 11 child.
