# M4 exit test

Date: 2026-09-04. Commit: `5765538`.

This note records the M4 exit test of spec `2026-09-02-m4-sim-design.md` section 1.2. The game was not run. The test client (`nw-testclient pair`) did the steps that two game clients do. The game cannot finish DTLS with this gateway (M3 spec section 1.3).

**Later finding.** A patched copy of the client now finishes DTLS and enters the world (`2026-09-06-cert-bypass-patch-plan.md`, `scripts/patch-client.py`).

## Set-up

- One PC. Docker PostgreSQL, Valkey and NATS.
- `edge-http migrate`, then `edge-http serve` with the operator's own domain and certificate, on port 8443 (`NW_EDGE_HTTPS_LISTEN`). The test client does not need port 443, so the program needs no extra right after a new build.
- `sim` with the committed `config/sim.toml` and the world file of client build 22469132 (`newworld_vitaeeterna`). The start check found the start position on the ground.

**Later finding.** The build 22469132 world file is deleted. `local-data/content/` now holds build 25810808 files only. This test cannot be re-run as written.
- `rep-gateway serve` with the committed `config/rep-gateway.toml`.
- `nw-testclient pair` with a local copy of `config/nw-testclient.toml`: the domain URLs with port 8443, the committed route (4 m east, 4 m north, 4 m west, at 1.65 m/s), `jump_m` 50, `hold_seconds` 60.
- The secrets are in a git-ignored local file.

**Observed.** The test client printed these lines (exit code 0):

```text
every session registered: pass
login messages in the captured order: pass
each client saw the other: pass
the walk was seen on the route: pass
the far move was refused: pass
the next login is at the saved position: pass
```

**Observed.** The gateway logged `registration accepted` 3 times. `sim` logged `joined` 3 times. Neither logged a warning or an error during the run. After the gateway stopped, `sim` logged `gateway silent; its players leave`, as section 11 says.

## What this proves

- Criteria 3.1 to 3.5 of section 1.2, between programs that this project wrote, on the real world file: two clients register, get the login messages in the captured order, and see each other. The second sees the first walk the route within 1.0 m. A move 50 m away is refused, and the first client keeps its last good position. A new login appears at the saved position within 0.1 m.
- The walk stayed inside the ground band of the real level near the start position.

## What this does not prove

- The game itself in the world. That is blocked by the game's built-in certificate trust, and this project does not change it.
- How the game reacts to a refused move (Unknown). The test client only checks the positions in its bundles.
- Falls from more than 64 m above the ground. The captures have falls of up to 128.6 m (movement numbers note, Check section); `max_height_above_ground_m` is 64.
