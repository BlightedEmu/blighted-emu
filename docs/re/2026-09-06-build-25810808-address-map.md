## Method

**Observed.** The old project was opened read-only. It was not changed. A new project holds the new build. The new build had a full auto-analysis before this work.

**Observed.** Ghidra Version Tracking ran on the new project. The old program was the source. The new program was the destination. The session is `NW-vt-exact`. Exact symbol, exact function bytes, and exact function instruction correlators were on. Implied matches were on. The duplicate function correlator was off. The exact data correlator was off. A first set of runs with the duplicate function correlator on ended with `OutOfMemoryError` in that correlator. Those runs gave no matches.

**Observed.** A parallel Python job ran at the same time. It used 16 workers. It hashed function bytes. It searched 32-byte and 16-byte anchor slices in the new `.text`. It searched byte slices and strings in the new `.rdata`. Scripts and logs: `<re-scratch>/nw-map/`. The game files are in `<game-dir>`.

**Observed.** The two tracks were merged. A Version Tracking match wins where both tracks agree. A Version Tracking match also wins where only Version Tracking has a match. The Python match wins where only the Python track has a match. Where the tracks disagreed, the bytes at each candidate were compared. The candidate with identical bytes, or the higher byte similarity, won. Each disagreement is logged.

**Observed.** Each cited function with body `changed` was decompiled in the old build and in the new build. The C text was compared. A short note on each change is below. If the only difference was an address, the body was set back to `unchanged`.
